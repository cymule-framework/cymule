# Documentation Guidance

- Write all documentation in English.
- Label behavior as `implemented`, `partial`, `proposed`, or `historical`.
- `specification.md` is normative. Architecture and research notes must not
  silently create new semantics.
- Keep one canonical explanation for each concept and link to it instead of
  copying it across files.
- User-facing documentation names capabilities directly. Reserve M0-M6 labels
  for the roadmap and maintainer-facing profile/specification cross-references.
- Any semantic object or transition added to documentation must map to code,
  schema, and a conformance test, or be explicitly marked proposed.
- Prefer technology-neutral property names. Concrete products may appear in
  research comparisons and adapter documentation, never as semantic authority.
- M4 authority is limited to one provider-neutral durable domain. Keep metrics,
  traffic movement, deployments, shadow sandboxes, schema transformation code,
  and Agent/session controllers explicitly outside the profile.
- `releasing.md` is the publication runbook. Keep package names, dependency
  order, immutable retry checks, OIDC-only trusted publishing, new-name
  ownership gates, current-controller/exact-payload separation, the three npm
  identity layers, and credential-removal requirements aligned with live
  workflows and scripts. Document `cymule.release-bom/3` as the terminal
  aggregate content receipt: fresh closed registry evidence,
  signed npm publisher ref/SHA, and required nullable publication for every
  source package remain distinct fields. The current finalizer SHA belongs to
  the run's stage, attestation and control-plane receipt, not immutable BOM bytes.
- Document the GitHub Artifact Attestation as the terminal content authority
  and an owner-enforced immutable GitHub Release as its discovery projection.
  Keep the exact tag-App creator, live App-slug/App-ID and distinct bot-user-ID
  readback, raw tag-object lost-ack binding, environment
  Team/admin-bypass policy, separate Administration-read live-preflight App,
  short-lived same-run control-plane receipt and settings-admin freeze window,
  single Release writer, and REST asset identity readback explicit; do not imply
  GitHub offers a conditional draft-publish CAS.
- Register every one-time store, data, or external control-plane transition in
  `migrations/README.md`. An executable runbook must distinguish source
  implementation from operator execution and include owner, scope, preflight,
  stop conditions, rollback, verification, and a non-secret execution record.
- `versioning/version-domains.json` owns the version inventory.
  `docs/version-domains.md` is generated by `scripts/version_domains.py`; never
  hand-edit its table or reintroduce a competing table in the specification.
- `plugins.md` is the current user-facing adapter catalog. Keep implementation
  status, limitations, mature foundations, and RocksDB/P1 guidance aligned with
  live crates and focused suites.
