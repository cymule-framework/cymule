# Pre-StateRoot Store Generations

Status: implemented rejection; migration unsupported.

The current directory `/5` and SQLite `/6` adapters accept only their typed
StateRoot physical generation. They contain no decoder, importer, or
compatibility route for predecessor whole-state or checkpoint/segment storage.
A `state.json` file, `cymule_state` table, or older physical marker fails with
`unsupported_store_generation` before the adapter creates any current marker,
head, StateRoot object, or table authority.

This is an intentional terminal decision. The removed `migrate_v1` functions
decoded a whole-state physical shell directly into the then-current
`cymule.durable-state/3` type; the current source generation uses exact-reject
`cymule.durable-state/7` with `cymule.machine-snapshot/11` behind
`cymule.durable-state-root/4`. They therefore never supported bytes produced by
the `66a432c45c81a74dfa3b030783a75ad7df5b772e` source generation, whose payload
contains `cymule.durable-state/1`, `cymule.machine-snapshot/1`, and earlier
semantic records. Keeping those functions would advertise a migration edge
that did not exist.

The later pre-release `cymule.durable-state/5` and `/6`, directory-store `/3`
and `/4`, SQLite-store `/4` and `/5`, and `cymule.durable-control/2` and `/3`
generations are also unsupported inputs to the current `/7` state, directory
`/5`, SQLite `/6`, and control `/4` authorities. They have no runtime reader or
migration edge; internal fixtures must be rebuilt from current source rather
than reinterpreted through the StateRoot, reconciliation, and receipt contracts.

The same rebuild-only boundary applies to Agent command/receipt `/2`, Agent
schema `/6`, Resource pin-current `/1`, and lifecycle-receipt-ref `/2` records.
Their successors add the external-stream pre-publication reservation, the
`Reserved` pin state, and an explicit Agent-reservation lifecycle locator.
Predecessors cannot represent the physical-family obligation that must win its
CAS before provider I/O, so no compatibility decoder or inferred reservation is
valid.

The current StateRoot `/4`, value `/4`, and Run-query-index `/3` generations
also hard-reject their pre-release `/3`, `/3`, and `/2` predecessors. The older
Run Wait query index pointed at complete Wait leaves and could compile as many
as 256 retained Input schemas during one page read. The current index instead
stores a same-CAS bounded summary leaf and keeps the complete Wait only behind
exact/audit paths. There is no in-place reader or converter for the superseded
graph; internal test stores must be rebuilt from current source.

The frozen fixture
`tests/fixtures/directory-store-66a432c-empty-state.json` was generated by the
exact `66a432c45c81a74dfa3b030783a75ad7df5b772e` code with Rust 1.97.1. Its
metadata records the emitted payload digest and the repository-only trailing
newline rule. Directory Store tests reconstruct those exact writer bytes,
require both writable and read-only open to return the stable unsupported
generation error, and prove that neither the payload nor any current StateRoot
authority is created or changed.

## Serving domains

A retained domain stays bound to the exact generation that wrote it. New
admission may route to a newer generation, while the old runtime drains its own
Runs and settles its pinned or unknown effects. There is no decode-failure
fallback and no dual writer.

Moving a live domain or Run requires one single-writer transfer:

1. the source CAS commits a transfer fence and stops new admission;
2. the source derives an exact immutable cut;
3. the target idempotently imports and verifies that cut;
4. routing authority moves to the target; and
5. the source retains only reconciliation and archival duties.

The repository does not implement that transfer protocol today. Until a real
consumer and complete fault suite justify it, active transfer remains
unsupported rather than approximated by copying mutable storage.

## Future offline migration

An offline migrator may be introduced only for a non-serving domain with no
reader or writer. It must use a frozen source decoder or an exact old-runner
export plus a new-runner verify/import protocol, identify the complete source
tuple in the version-domain registry, and record old-to-new identity and
revision mappings. Reusing a current type to deserialize old bytes is not a
migration.
